ECS terms

Task definition

A task definition is the container blueprint. It specifies the Docker image, CPU, memory, container ports, environment variables, IAM roles, logs, and volumes such as EFS.

Image: todo-app
Port: 3000
DB_HOST: mysql.todo.local
Memory: 512 MB

Task

A task is one running instance created from a task definition. ECS can replace it if it stops.

Task definition: todo-app:1
Running tasks: 1

Service

An ECS service manages running tasks. It defines the task definition, desired count, networking, subnets, security groups, public IP assignment, service discovery, and restart behavior.

Service: todo-service
Task definition: todo-app:1
Desired count: 1

Relationship: task definition = blueprint → ECS service = manager → task = running container. Jenkins updates the services, and ECS replaces their running tasks using the configured task definitions.

Create manually before Jenkins

  1. VPC and subnets: Put the frontend in a public subnet. Put backend and MySQL in private subnets. For a temporary test without NAT, backend and MySQL can use public subnets with public IP assignment disabled.
  2. Security groups: Frontend allows TCP 80 from your test network. Backend allows TCP 3000 only from frontend. MySQL allows TCP 3306 only from backend. Never allow MySQL from the internet.
  3. ECR repositories: Create todo-frontend, todo-app, and todo-mysql.
  4. ECS cluster: Create todo-cluster using Fargate.
  5. IAM roles: Create an ECS task execution role with ECR pull and CloudWatch Logs permissions.
  6. EFS: Create EFS mount targets in the private-subnet Availability Zones and mount EFS at /var/lib/mysql.
  7. Service discovery: Create private DNS namespace todo.local. Register backend as todo-service and MySQL as mysql, producing mysql.todo.local.
  8. Task definitions: Create frontend port 80, backend port 3000, and MySQL port 3306. Configure the environment variables below.
  9. ECS services: Create todo-mysql-service, todo-service, and todo-frontend-service with desired count 1.
  10. No-ALB access: Set assignPublicIp: ENABLED only for the frontend service and open its task public IP.
  11. Private task egress: Backend and MySQL need a NAT Gateway or suitable ECR and CloudWatch VPC endpoints.

Jenkins setup

Jenkins agent

  • Linux agent with Docker
  • AWS CLI installed
  • Pipeline and AWS Credentials Binding plugins
  • Network access to ECR and ECS APIs

Credentials

  • aws-credentials: AWS credential
  • aws-region: secret text such as us-east-1
  • ecr-registry: ECR registry hostname
Pipeline order: build three images → push three ECR images → redeploy MySQL → wait → redeploy backend → wait → redeploy frontend.

After resources are ready

  1. Push this repository to GitHub.
  2. Create a Jenkins Pipeline job pointing to Jenkinsfile.
  3. Run with IMAGE_TAG=latest for testing.
  4. Wait for all three services to stabilize.
  5. Open the frontend task public IP on port 80.
  6. Sign in with any email and OTP 123456.
Important: Jenkins does not create AWS infrastructure, task definitions, service discovery, or EFS. Create those manually first.
